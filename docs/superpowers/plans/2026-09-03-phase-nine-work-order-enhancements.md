# Phase 9 Work Order Enhancements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Add secure work-order attachments and an immutable, operator-friendly work-order history while preserving the existing photo and public appointment-confirmation flows.

**Architecture:** WorkOrderAttachment and WorkOrderHistoryEntry are owned by WorkOrder, persist as tenant-scoped EF Core entities, and load through the existing work-order repository. Application use cases record concise history entries beside their mutations; attachment I/O stays behind IFileStorage. The authenticated work-order detail and execution panel render attachments and history from its DTO.

**Tech Stack:** .NET 10, C#, ASP.NET Core Minimal APIs, Blazor, MudBlazor, EF Core, PostgreSQL, xUnit.

**Spec:** docs/superpowers/specs/2026-09-03-phase-nine-work-order-enhancements-design.md

## Global Constraints

- Source-code names, database names, migration names, test names, and technical messages are English; UI copy is Brazilian Portuguese.
- CompanyId comes from the current authenticated context, never the browser; every read and mutation enforces tenant and professional access.
- Domain and Application use TimeProvider; no direct machine-clock calls.
- Keep photos specialized in WorkOrderPhoto; attachments must not replace or alter before/after photo requirements.
- Do not add generic repositories, generic attachments, new frameworks, or external storage dependencies.
- All files use apply_patch; no destructive git operations.

~~~csharp
public enum WorkOrderHistoryEventType
{
    Created, DetailsUpdated, ProfessionalAssigned, Started, ChecklistProgressSaved,
    ExecutionNotesUpdated, PhotoAdded, PhotoRemoved, AttachmentAdded,
    AttachmentRemoved, AdditionalItemsUpdated, Completed, Cancelled
}

public WorkOrderAttachment AddAttachment(string fileKey, string originalFileName, string contentType, long length, string? description, Guid uploadedByUserId, DateTimeOffset now)
{
    EnsureInProgress();
    var attachment = WorkOrderAttachment.Create(CompanyId, Id, fileKey, originalFileName, contentType, length, description, uploadedByUserId, now);
    _attachments.Add(attachment);
    UpdatedAtUtc = now.ToUniversalTime();
    return attachment;
}
~~~

Validate non-empty identifiers, key/name/content type, positive length, 1,000-character keys/descriptions, and a 255-character original filename. History validates a defined event, non-empty 1,000-character description, and normalizes UTC. Configure both tables with the compound WorkOrder foreign key and chronological indexes named IX_WorkOrderAttachments_CompanyId_WorkOrderId_CreatedAtUtc and IX_WorkOrderHistoryEntries_CompanyId_WorkOrderId_CreatedAtUtc. Include both collections in GetForAccessAsync.
